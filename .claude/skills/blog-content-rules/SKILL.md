# 블로그 글 생성 규칙

`research.js` → `content.js` → `blocks.js` 파이프라인의 규칙과 수정 절차.

## 파이프라인

```
research.js    네이버 자동완성 연관 검색어 + 검색 API 소재(뉴스·백과, 블로그 제외) + researchLatest(키워드 조합 최신 기사: Bing·Google 뉴스 RSS, 키 있으면 네이버 뉴스 최신순 — 네이버 블로그는 찾지 않고 blog.naver.com 주소도 버림(2026-10-26 사용자 요청). 아기 키워드는 소아·영유아로도 찾고, 앞쪽 6건은 readArticles 가 원문 요약 420자를 읽음 — Google 링크는 못 엶)
    ↓
topics.js      연관 검색어 뒷말의 의도를 9분류 → 의도별 소제목·문단
    ↓
content.js     제목·태그 생성, AI 지시문, 내장 글 틀, normalizeDraft
    ↓  (gemini.js / ollama.js 중 하나, 또는 내장 글 틀)
style.js       합니다체 교정, 과장어 제거, 조사 교정, 글자수
    ↓
blocks.js      초안 → 에디터 블록 (크기·색·굵게·구분선·이미지 슬롯)
```

`normalizeDraft` 가 **세 엔진의 출력을 하나의 모양으로 맞추는 지점**이다. 여기를 건드리면 세 경로를 모두 재확인한다.

## 숫자 계약 — 임의로 바꾸지 않는다

사용자가 정한 값이다. 바꿀 이유를 찾았으면 먼저 보고하고 승인을 받는다.

| 항목 | 값 | 정의 위치 |
|---|---|---|
| 본문 글자 크기 | 15px | `blocks.js` `SIZES.body` |
| 소제목 | 네이버 인용구 상자(`quote` 블록). 인용구를 못 넣으면 19px 네이비 글자 | `blocks.js` `pushQuote`, `naver.js` `insertQuote` |
| 캡션 크기 | 13px | `blocks.js` `SIZES.caption` |
| 소제목 색 | `#1f4e79` 네이비 | `blocks.js` `COLORS.heading` |
| 중요 문장 색 | `#e8590c` 주황, 굵게 쓰지 않음 (글 전체에 굵은 글씨 없음) | `blocks.js` `COLORS.accent` |
| 질문·보조 강조 색 | `#1b6ec2` 파랑 | `blocks.js` `COLORS.point` |
| 키워드 반복 | 메인 키워드는 본문 문장에 4~5회(서론 1·본론 2~3·결론 1, `MAIN_BODY_MIN/MAX`), 서브 키워드는 구역마다 1회, 사진 설명 0회, 나머지는 줄인 말. 키워드 나열·한 문장 몰림 금지(`keywordIssues` → 키워드 고치기). 제목·소제목은 세지 않음 | `content.js` `limitKeywords`, `keywordIssues` |
| 구분선 색 | `#6b7280` 회색 | `blocks.js` `COLORS.soft` |
| 글자수 | 공백 제외 약 2000자(1800~2200자, `BLOG_MIN_CHARS`). 1800자 미만이면 늘려 쓰기 1회, 2300자(115%) 초과면 줄여 쓰기 1회(`shrinkFrom`, 줄었고 1600자 이상·AI 소제목 수 같을 때만 채택). 인사말·요약·태그·사진 설명은 세지 않음. 화면엔 공백 포함도 함께(`charCountWithSpaces`). 2026-10-26 사용자 요청 — 공백 포함 3000자 이상을 대체 | `style.js` `countChars`, `content.js` `targetRange`, `main.js` |
| 소제목 개수 | 3~4개, 메인 + 서브 키워드마다 하나(모자라면 연관 검색어) | `content.js` `sectionKeywordsOf` |
| 태그 개수 | 5~7개 | `content.js` `cleanTags`, `makeTags` |
| 이미지 슬롯 | 대표 1 + 본문 사진 수(`[사진: 설명 \| 영어]` 표시마다, 없는 소제목엔 1장 자동) | `blocks.js` `imageSlots` |
| 단락 길이 | 한 단락 최대 3문장 | `content.js` `shapeParagraphs` |
| 제목 | AI 추천 3개(메인 키워드 앞쪽 + 서브 키워드 1~2개 조합, 20~35자). 한 제목에 ① 통념 뒤집기(예외적 상황·반전, 사실이어야 함) ② 직관적인 숫자(아라비아 숫자, 본문에서 실제로 다루는 수치만) ③ 클릭을 부르는 말("믿었는데 알고 보니", "결국 ~하더라", "싹 다 무너짐", "장난 아니게") 중 최소 2가지, 되도록 3가지. 밋밋한 "~궁금하다면/총정리"·사실 아닌 단정("100% 효과") 금지. AI 는 후보 3개를 좋은 순서로 주고 프로그램이 하나만 자동으로 고름(`penalty`: 어색함 10 > 본문에 없는 숫자 5 > 메인 키워드 빠짐 4 > 밋밋한 꼴 3 > 숫자 없음·길이 2, + AI 순서), 미리보기에서 고르지 않음. **지정 제목**(화면 글 목록의 줄마다 제목 칸, 글쓰기.bat 의 `--titleN`)을 넣으면 글자 하나 바꾸지 않고 그 제목을 씀: 지시문에 "지정 제목" 규칙(제목이 묻는 것에 도입부에서 바로 답, 제목의 대상·숫자·개수를 본문에서 빠짐없이, 사실과 다르면 지어내지 않음), 교정 단계도 안 바꿈, `normalizeDraft` 끝에서 조사 고치기·기준 시점 지우기 뒤 지정 제목으로 되돌림 | `content.js` `titles`, `renderer/app.js` |
| 문장 종결 | AI 글: `BLOG_TONE` 기본 casual — 친근하고 몰입감 있는 구어체 `~해요·~거든요·~더라고요·~죠` 중심 + `~합니다` 가끔(`style.js` `tidy`, 말끝 안 바꿈). formal 이면 합니다체(`formalize`). 경험담 형태지만 글쓴이 1인칭("저는") 금지 — 대중 경험을 이야기처럼(2026-10-08 사용자 선택). 기본 틀: 합니다체(`toFormal`) | `content.js` `formalTone`, `style.js` |

**색과 크기는 `COLORS`/`SIZES` 상수만 고친다.** 값을 다른 파일에 하드코딩하면 한쪽만 바뀌어 틀어진다.

## 글 구조

| 순서 | 내용 |
|---|---|
| 이미지 | 맨 위 썸네일 1장(`BLOG_TOP_IMAGE` 기본 on — off 면 안 만듦): GPT 가 제목의 궁금증을 부르는 장면을 그리고(`images.js` `THUMBNAIL_SCENE`), `imagelab.js` `drawOverlay` 가 AI 의 `thumbnail.text`(2줄, 없으면 제목)를 아래쪽에 크게 얹음. 본문 사진엔 글씨 없음 |
| 도입부 | 인사말 바로 다음(서론 사진 다음) 첫 문장부터 제목이 던진 궁금증의 답을 바로 말함(반전의 이유·숫자의 뜻·어떻게 하면 되는지 2~3문장). "끝까지 읽으면", "이 글에서는 ~ 알려 드릴게요" 같은 예고·뜸 들이기, 정의·일반론 금지. 둘째 단락부터 근거·흔한 오해, 자세한 내용은 본론. 교정 단계(8번)가 남은 예고 문장을 답·근거 문장으로 바꿈. 키워드 고치기·늘려 쓰기도 이 구성 보존. 메인 키워드 1회 |
| 본론 | 키워드별 소제목 3~4개(인용구 상자). 단락 5개 안팎: 첫 3~4줄(첫 단락)에 강한 공감·"나도 이런데?" 훅, 중간에 다른 사람들의 경험담·팁이 녹아든 예시(특정 인물·병원·상품 이름은 지어내지 않음), 전문 정보 3단락(경험담·팁 1단락). 짧고 간결한 구어체(~해요·~거든요), AI 티 나는 상투적 인사·도입 문구 금지. 사진은 AI 표시 자리 |
| 결론 및 맺음말 | 글 전체 요약 → 끝에 댓글 참여·공감을 부르는 질문 1~2문장(`conclusion.question`, 기본 글자색). AI 가 안 주면 결론 끝 부탁 문장을 옮기거나 기본 질문(`questionOf`). 본문 단락의 부탁 문장은 `dropAsks` 가 지움. 총평·별점 없음 |
| 해시태그 | 5~7개 한 줄 |

전체 글 목록·간단 요약·마무리 이미지는 2026-10-01 사용자 지정 구조에서 빠졌다.

## AI 지시문의 방향 (2026-10-01 사용자 요청)

주제 자체에 대한 전문 정보, 최신 정보(글 쓰기 전 main.js 가 키워드를 조합해 최신 기사를 찾아 참고 자료 맨 앞에 최신순으로 둠 — 메인 키워드 핵심 낱말이 모두 든 2년 안 기사만, 3건 미만이면 서브 키워드만으로도. 아기·아이 키워드는 "영유아·소아·신생아·어린이·아동"도 같은 낱말(`hasToken`)·"소아/영유아 ○○" 검색어(`kidQueries`). 앞쪽 6건은 원문 요약(`readArticles`, `BLOG_READ_ARTICLES`), 찾은 기사는 `draft.latestNews` 와 진행 기록에 남김. 참고 자료는 한 건 480자·전체 약 4200자(로컬 AI 한도). 지시문 6번: "::" 뒤는 원문 요약·주제와 맞는 최근 소식은 반드시 한 번 이상 반영·제목만 있는 기사는 제목의 사실만·다른 나라 소식은 국내 기준처럼 안 씀· 가장 최근 날짜 우선·지역 소식은 예로만·언론사 이름 안 씀. 기준 시점 문구("2026년 ○월 발표 기준", "2026년 기준으로", "최신 기준으로", "(○월 기준)")는 쓰지 않음 — 지시문 6번·교정 10번에서 금지하고 AI 가 써 오면 `dropAsOfDraft` 가 문구만 지움(제목·본문·요약·질문·사진 설명·썸네일 문구, 채팅 모드 포함, 키워드에 "기준"이 있으면 안 건드림, "기준 중위소득"·"1월 1일 기준으로 만 34세" 같은 용어·자격 날짜는 둠). `BLOG_LATEST_NEWS=off` 로 끔. Gemini 구글 검색은 키 한도 429 면 건너뜀), 기승전결 스토리텔링, 구체적 장면·항목, 결론은 소제목 핵심을 이은 전체 요약. 일반론("검색해 보세요", "메모해 두세요") 금지. highlight 는 정말 중요한 것만, 없으면 빈 문자열 허용. 내장 틀은 주제 지식이 없으므로 전문 글은 AI 키가 있어야 나온다 — 내장 틀을 아무리 고쳐도 이 요구는 충족되지 않는다.

## 지어낸 사실을 쓰지 않는다

`topics.js` 의 설계 의도가 이것이다. 시험 날짜, 금액, 기간, 합격률 같은 **수치를 생성하지 않고** "확인하는 방법"을 쓴다. 시점을 물으면 기간 확인법을, 비용을 물으면 금액 따지는 법을, 준비물을 물으면 고르는 기준을 쓴다.

AI 지시문(`content.js` 의 `buildPrompt`, `gemini.js`/`ollama.js` 의 `SYSTEM`)을 수정할 때도 이 원칙을 깨지 않는다. 블로그 글의 신뢰성이 걸린 문제이고, 틀린 수치는 독자에게 실질적 피해를 준다.

## 소제목 의도 9분류

`topics.js` 의 `CATEGORIES` 가 연관 검색어 뒷말을 보고 무엇을 묻는지 분류한다: 시점 / 방법 / 비용 / 준비물 / 기준·자격 / 장소 / 증상·원인 / 비교·추천 / 기타.

**분류를 추가할 때 `match` 정규식이 기존 분류와 겹치지 않는지 확인한다.** `categoryOf` 는 `CATEGORIES.find` 를 쓰므로 **앞선 분류가 항상 이긴다.** 겹치면 새 분류는 영원히 선택되지 않는다. 배열 순서상 뒤에 넣을 때는 특히 주의한다.

**소제목 의도가 겹치면 글이 반복적으로 읽힌다.** `pickModifiers` 가 같은 분류를 중복 선택하지 않게 만든 이유다. "글이 반복적이다"는 피드백은 거의 항상 이 함수 또는 `modifiersOf` 의 문제이고, 문장 표현의 문제가 아니다.

같은 분류가 두 번 나와도 다른 문장이 나오도록 `buildTopicSection` 이 `index` 로 번갈아 쓴다. 분류별 문장 변형을 추가할 때는 이 교대 구조를 유지한다.

## 문체 교정 — 확실한 경우만 바꾼다

`style.js` 가 애매한 표현을 **그대로 두는 이유**는, 잘못 바꾸면 문장이 망가지기 때문이다. 교정 규칙을 넓히면 오작동이 늘어난다.

**조사 교정은 명사가 확실한 말 뒤에서만 한다.** `fixParticlesFor` 가 키워드 목록을 받는 이유다. 아무 단어 뒤에서나 받침을 보고 조사를 고치면 다른 문장을 깨뜨린다.

**물음표로 끝나는 문장은 그대로 둔다.** `toFormal` 이 물음표를 건드리지 않고, `QUESTION_ENDINGS` 로 바꿀 수 있는 형태만 따로 처리한다. 결론의 댓글 유도 질문이 여기 해당한다.

**교정 규칙을 넓힐 때는 오작동 사례를 먼저 찾는다.** 규칙을 추가한 뒤 실제 초안을 생성해 다른 문장이 망가지지 않았는지 확인한다. `data/drafts/` 의 직전 초안과 비교하면 변화를 빨리 볼 수 있다.

## 3중 폴백은 가용성 설계다

Gemini 키가 없어도, 인터넷이 없어도, Ollama 가 꺼져 있어도 1500자 글이 나와야 한다. 이것이 품질 저하 허용이 아니라 **이 앱의 핵심 설계**다.

| 엔진 | 조건 | 특성 |
|---|---|---|
| Gemini | `GEMINI_API_KEY` 있음 | 품질 최상, 20~60초 |
| Ollama | 로컬 서버 응답 | 키 불필요, 1~5분, `OLLAMA_TIMEOUT` 기본 10분 |
| 내장 글 틀 | 항상 | 즉시. `topics.js` 의 의도별 문단으로 구성 |

`자동` 모드는 Gemini → Ollama → 내장 틀 순서로 떨어진다.

**어떤 엔진을 수정하든 나머지 두 경로가 여전히 동작하는지 확인한다.** AI 응답이 JSON 이 아니어도 `extractJson` 이 처리하고, 그것도 실패하면 내장 틀로 떨어져야 한다. **사용자에게 에러를 던지지 않는다.**

글자수가 모자라면 에러가 아니라 내용을 더 채우는 것이 설계된 동작이다.

## 블록 타입은 소비자가 셋이다

`blocks.js` 가 만드는 `block.type` 은 세 곳이 소비한다:

| 소비자 | 위치 |
|---|---|
| 키스트로크 입력 | `naver.js` 의 `typeBlocks` |
| 붙여넣기 입력 | `naver.js` 의 `pasteBlocks` |
| 미리보기·붙여넣기 HTML | `blocks.js` 의 `blocksToHtml` |

현재 타입: `text`, `image`, `blank`, `quote`(소제목 인용구). 구분선은 별도 타입이 아니라 `· · ·` 를 회색 가운데 정렬 `text` 로 넣는다.

**새 타입을 추가하면 세 곳 모두 처리해야 한다.** 빠뜨리면 블록이 **에러 없이 조용히 사라진다.** `text` 는 기본 분기(else)로 처리되므로 명시적 비교가 없어도 정상이다.

추가 후 반드시 대조한다:

```bash
node .claude/skills/boundary-audit/scripts/boundary-check.mjs
```

그리고 `naver-automation` 에게 통보한다.

## 검증 절차

글 생성은 **API 키 없이도 검증 가능하다.** 내장 글 틀 경로로 실제 초안을 만들어 규칙 위반을 확인한다.

```bash
# Electron 전체 파이프라인 (글 + 이미지까지, 브라우저 자동화 없음)
npx electron . --selftest
# 결과: data/selftest.json
```

내장 글 틀만 빠르게 보려면 Node 로 모듈을 직접 호출한다. `GEMINI_API_KEY` 를 비우고 `localDraft` → `normalizeDraft` → `buildBlocks` 를 순서대로 실행해 결과를 검사한다.

### 최소 확인 항목

- 공백 제외 글자수 1800~2200 (`countChars`, AI 글 기준 — 기본 틀은 주제 지식이 없어 못 채울 수 있음)
- 모든 문장이 `합니다 / 습니다 / 입니다` 로 끝남 (물음표 문장 제외)
- 해요체 잔존 없음
- 소제목 5개 이상, 의도가 중복되지 않음
- 태그 10개
- 블록의 `size`·`color` 값이 `SIZES`/`COLORS` 와 일치
- 이미지 슬롯 수 = 1 + 소제목 수 + 1

**규칙 간 충돌이 생기면 임의로 한쪽을 버리지 않는다.** 예를 들어 1500자 달성과 중복 없는 소제목이 상충하면(연관 검색어가 적게 수집된 경우) 보고한다.

## 이전 산출물이 있을 때

`_workspace/` 의 이전 산출물과 `data/drafts/` 의 직전 초안을 함께 읽는다. 사용자가 "이 부분이 어색하다"고 지목했으면 **해당 규칙만** 고치고 전체 글 틀을 다시 쓰지 않는다.

피드백은 일반화해서 반영한다. "이 문장이 어색하다"를 그 문장만 예외 처리하지 말고, 어떤 규칙이 그 문장을 만들었는지 찾아 규칙을 고친다. 특정 사례에만 맞는 수정은 다음 글에서 같은 문제를 다시 만든다.

## 사진 검색어 사전은 공유 자원이다

`topics.js` 의 `TOPIC_HINTS` / `topicImageHint` 는 한국어 주제어를 영어 사진 검색어로 바꾼다 (아기 → baby hands, 제과기능사 → cooking kitchen). 이 사전은 `image-pipeline` 과 **공유**한다.

수정할 때는 `image-pipeline` 에게 통보해 동시 수정 충돌을 피한다. "사진이 주제와 안 맞는다"는 피드백의 1순위 해결책이 이 사전 확장이다.
