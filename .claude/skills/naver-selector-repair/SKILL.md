# 네이버 셀렉터 드리프트 복구

네이버가 에디터 DOM 을 바꿔 `src/naver.js` 의 자동화가 깨졌을 때 복구하는 절차.

## 왜 이 작업이 반복되는가

네이버 DOM 은 **통제할 수 없는 외부 계약**이다. 사전 공지 없이 바뀌고, 클래스 이름 접두사가 붙거나 빠지며, 요소 계층이 한 단 늘거나 줄어든다. 그래서 이 복구는 1회성 버그 수정이 아니라 **주기적으로 반복되는 유지보수**다. 복구할 때마다 "다음에 또 바뀌어도 버티는 구조"로 만드는 것이 목표다.

## 1단계: 증상에서 실패 지점을 특정한다

에러 메시지의 타임아웃 값이 실패 지점을 알려 준다. `src/naver.js` 는 용도별로 다른 타임아웃을 쓰기 때문이다.

| 증상 | 실패 지점 | 의미 |
|---|---|---|
| `locator.click: Timeout 15000ms` | 제목 입력 (`typeTitle`) | 에디터 프레임은 찾았으나 제목 칸 클릭 실패 |
| `editor-not-found` | `openWriteForm` | 두 글쓰기 URL 모두에서 에디터 프레임 자체를 못 찾음 |
| `title-box-not-found` | `findTitleBox` | 프레임은 찾았으나 보이고 크기 있는 제목 칸이 없음 |
| `title-focus-failed` | `focusTitleBox` | 제목 칸을 찾고 눌렀으나 커서가 들어가지 않음 (덮개 의심) |
| `login-timeout` | `resolveBlogId` | 5분 안에 로그인이 확인되지 않음. 셀렉터 문제가 아님 |
| 글자 크기·색이 안 들어감 | `setFontSize` / `setFontColor` | 툴바 셀렉터 불일치. 이 경로는 실패를 흡수하므로 에러가 안 남 |
| 임시저장 버튼 못 찾음 | `saveDraft` | 글은 들어간 상태. 저장 버튼 셀렉터만 불일치 |

**실패를 흡수하는 경로를 주의한다.** `clickSelector`, `setFontSize`, `setFontColor`, `insertImage`, `saveDraft` 는 모두 `.catch(noop)` 로 실패를 삼키고 로그만 남긴다. 에러가 안 났다고 성공한 것이 아니다. 진행 기록(log)에 "찾지 못했습니다" 메시지가 있는지 확인한다.

## 2단계: 실제 DOM 증거를 확보한다

**추측으로 셀렉터를 바꾸지 않는다.** 네이버 DOM 은 로그인 없이 볼 수 없으므로, 증거 없이 고치면 다음에도 같은 자리에서 깨진다.

`src/naver.js` 의 `dumpEditorDom` 이 실패 시점의 구조를 `data/logs/naver-dom-*.json` 에 남긴다. 먼저 이 파일을 찾는다:

```bash
ls -t data/logs/naver-dom-*.json | head -3
```

덤프에는 프레임별로 `titleish`(제목 관련 요소), `editables`(contenteditable 요소), `popups`(덮개) 가 각각 클래스명·크기·표시 상태와 함께 들어 있다. 여기서 실제 클래스명을 읽어 셀렉터 목록에 추가한다.

**덤프가 없으면 사용자에게 재현을 요청한다.** 덤프는 실패 경로에서만 생성되므로, 사용자가 한 번 더 실행해야 생긴다. "다시 실행해 주시고 `data\logs` 폴더의 `naver-dom-*.json` 파일을 알려 주시기 바랍니다"라고 요청한다. 덤프 없이 넓은 셀렉터를 추측으로 넣으면 오탐(엉뚱한 요소 선택)으로 더 진단하기 어려운 증상을 만든다.

## 3단계: 폴백 사다리로 수정한다

단일 셀렉터를 다른 단일 셀렉터로 교체하는 것은 복구가 아니다. 다음에 또 깨진다. **배열 상수로 폴백 사다리를 만든다.**

```js
// 앞쪽이 더 정확하고, 뒤로 갈수록 범위가 넓습니다.
const TITLE_SELECTORS = [
  '.se-section-documentTitle [contenteditable="true"]',
  '.se-documentTitle [contenteditable="true"]',
  // ... 중간 생략 ...
  '.se-section-documentTitle',   // 마지막은 컨테이너 자체
  '.se-documentTitle',
];
```

그리고 **보이고 크기가 있는 첫 요소**를 고른다. `count() > 0` 만으로는 부족하다 — 숨겨진 placeholder 나 크기 0 요소가 잡히면 클릭이 타임아웃한다:

```js
const box = await candidate.boundingBox().catch(() => null);
if (box && box.width > 20 && box.height > 5) { /* 채택 */ }
```

### 반드시 지킬 네 가지

**감지용과 조작용 셀렉터를 같은 목록에서 가져온다.** 이 둘이 어긋나면 "에디터는 찾았는데 클릭은 타임아웃"이라는 진단하기 어려운 증상이 나온다. 이 프로젝트에서 실제로 발생했다 — `.se-documentTitle` 로 감지하고 `.se-documentTitle [contenteditable="true"]` 로 클릭해, 후자가 0개라 15초를 기다리다 실패했다.

**CSS 클래스는 정확히 일치해야 한다.** `.se-documentTitle` 은 `class="se-section-documentTitle"` 을 **잡지 못한다**. 네이버는 `se-section-` 같은 접두사를 붙이거나 떼는 변경을 자주 하므로 변형을 모두 목록에 넣는다.

**요소를 찾기 전에 덮개를 닫는다.** 클릭 타임아웃의 1순위 원인은 요소가 없는 것이 아니라 "작성 중이던 글이 있습니다" 복구 팝업이나 도움말 패널이 화면을 덮은 것이다. Playwright 는 클릭 가능해질 때까지 기다리다 타임아웃한다. 닫기 버튼 후보를 넓게 두고 반복 시도하며, 그래도 덮개가 남아 있으면 Escape 를 누른다.

**네이버 쪽 덮개 창(클래스가 해시인 `layer_popup__… isShow__…`)도 덮개다.** 2026-10-23 상단 "저장 | 15" 의 숫자로 여는 "임시저장 글" 목록 창이 글을 쓰는 동안 열려 있었다. `se-` 클래스가 아니어서 닫기 후보·덮개 감지 모두에서 빠졌고, `dimmed__…` 덮개가 도구 모음 클릭을 막고 `data-focus-lock` 이 키보드 초점을 창 안에 가둬 28분 동안 본문·글자 크기가 들어가지 않았다. 닫으면 초점이 그 창을 연 단추로 돌아가 다음 Enter 가 창을 다시 연다. 창 안에서 Enter 가 눌리면 예전 임시저장 글을 불러올 수 있다. 그래서 `typeBlocks` 는 블록마다 키를 누르기 전에 `keepFocusInBody` 로 창을 닫고 초점이 본문 밖이면 본문 끝으로 되돌린다. 증거: `mock-typing-test.mjs` 변형 F(수정 전 코드는 줄 누락 + 예전 글 불러옴).

**커서 올리기를 3단계로 한다.** 일반 클릭 → `force: true` 클릭 → 자바스크립트 직접 포커스(`focus()` + `Range` 로 커서 끝 이동). 일반 클릭만으로는 덮개나 이벤트 가로채기에 막힌다.

**스마트에디터 ONE 은 제목·본문 요소가 아니라 숨은 입력칸으로 키를 받는다.** 실제 덤프(2026-10)에서 제목 요소들은 모두 `contenteditable` 이 없고, 화면 구석의 폭 17px 짜리 숨은 `contenteditable` 하나가 키 입력을 받아 제목 칸에 그려 준다. 그래서 "`document.activeElement` 가 제목 요소 안에 있는가"로 성공을 판단하면 **실제 에디터에서는 항상 실패한다.** 이 판정 때문에 `title-focus-failed` 가 반복되고, 사용자가 다시 누를 때마다 페이지 이동이 일어나 "새로고침되고 글이 안 들어간다"는 증상으로 보였다. 포커스는 "에디터의 편집 가능한 요소 어딘가에 갔는가"만 보고, 성공 여부는 **입력 후 제목 칸 글자를 읽어** 판정한다.

## 4단계: 입력 결과를 확인한다

키보드 입력은 **포커스가 엉뚱한 곳에 있어도 에러 없이 조용히 실패한다.** 이것이 "고쳤는데 제목이 비어 있다"의 원인이다. 입력 후 해당 요소의 텍스트를 읽어 검증하고, 안 들어갔으면 한 번 재시도한다:

```js
const entered = await found.locator
  .evaluate((node, text) => (node.textContent || node.value || '').includes(text), sample)
  .catch(() => true);
```

`.catch(() => true)` 로 기본값을 `true` 로 두는 이유: 검증 자체가 실패했을 때 무한 재시도를 막기 위해서다.

## 5단계: 모의 DOM 으로 검증한다

**검증 없이 "고쳤습니다"라고 보고하지 않는다.** 실제 네이버는 로그인이 필요해 테스트할 수 없으므로, 번들된 스크립트로 DOM 변형 6종에서 셀렉터가 동작하는지 확인한다:

```bash
node .claude/skills/naver-selector-repair/scripts/mock-editor-test.mjs
```

이 스크립트는 `src/naver.js` 가 내보내는 `__test.typeTitle` 을 **그대로 호출**한다. 테스트 안에 로직을 베껴 두지 않는다 — 예전에 로직을 베껴 시험했더니, 실제 코드가 틀렸는데도 테스트는 통과했다. 새 함수를 검증하려면 `__test` 에 추가해 내보낸다.

검증하는 변형(8종): 내부 editable 구조, `se-documentTitle` 자체가 editable, 레거시 `textarea`, `se-title-text` 문단, 복구 팝업, placeholder 만 있는 제목, **스마트에디터 ONE 실제 구조(숨은 입력칸, G)**, G + 복구 팝업(H).

변형 목록 확인은 `--list`, 일부만 실행은 `--only=B,G`.

### 모의 DOM 이 통과하는데 실제가 실패하면, 모의 DOM 이 틀린 것이다

2026-10 에 6종 모두 통과하는데 실제 에디터는 실패했다. 원인은 변형들이 전부 "제목 요소가 직접 편집 가능하다"는 같은 가정을 공유했기 때문이다. 실제 덤프와 다르게 생긴 변형만 있으면 테스트는 아무것도 보장하지 못한다. 덤프를 받으면 **그 구조를 그대로 변형으로 추가하고, 수정 전 코드로 그 변형이 실패하는지 먼저 확인한다.** 실패를 재현하지 못한 변형은 회귀를 잡지 못한다.

### 새 실패 모드를 발견하면 변형을 추가한다

덤프에서 지금까지 없던 구조를 발견하면, 스크립트의 `VARIANTS` 배열에 그 구조를 추가한다. 그래야 다음 복구에서 회귀를 잡는다. 변형은 누적만 하고 지우지 않는다 — 네이버는 과거 구조로 되돌아가기도 한다.

## 6단계: 통과의 의미를 정확히 보고한다

모의 테스트 통과는 **"회귀가 없다"**는 뜻이다. **"실제로 동작한다"는 보장이 아니다.** 네이버가 완전히 새로운 구조를 쓰면 6종 모두 통과하고도 실패한다.

보고에 이 구분을 명시한다:

```
모의 DOM 6종 통과 (회귀 없음 확인).
실제 네이버 에디터는 로그인이 필요해 검증하지 못했습니다.
실행 후 또 실패하면 data\logs 의 naver-dom-*.json 을 알려 주시기 바랍니다.
```

검증하지 않은 것을 통과로 쓰지 않는다.

## 7단계: 새 에러 코드는 한국어 안내와 짝을 맞춘다

새 실패 경로를 만들어 `throw new Error('새-코드')` 를 추가하면, `main.js` 의 messages 맵에 한국어 안내를 **반드시** 추가한다. 맵에 없으면 영어 코드가 그대로 사용자 화면에 노출된다 — 이 프로그램의 사용자는 개발자가 아니다.

`app-shell` 에게 알리고, 다음으로 짝이 맞는지 확인한다:

```bash
node .claude/skills/boundary-audit/scripts/boundary-check.mjs
```

안내 문장은 사용자가 **무엇을 해야 하는지** 알려 준다. "title-box-not-found" 가 아니라 "제목 칸을 찾지 못했습니다. `data\logs` 폴더의 `naver-dom` 파일을 확인해 주시기 바랍니다".

## 셀렉터를 넓힐 때의 위험

넓은 셀렉터는 오탐을 만든다. `.se-title-text` 같은 컨테이너 셀렉터가 본문 영역의 요소를 잡으면, 제목 대신 본문에 제목이 입력된다 — 에러가 안 나므로 발견이 늦다.

오탐을 막는 방법:
- 보임·크기 조건을 함께 건다 (3단계 참조)
- 넓은 셀렉터는 목록의 **뒤쪽**에 둔다. 앞쪽의 정확한 셀렉터가 먼저 채택된다
- 제목 영역에만 있는 클래스를 쓴다. `.se-text-paragraph` 는 본문에도 있으므로 단독으로 쓰지 않고 `.se-title-text .se-text-paragraph` 처럼 조상을 함께 지정한다

## 하지 말 것

**네이버 로그인을 자동화하지 않는다.** 아이디·비밀번호를 코드나 `.env` 에 넣어 자동 입력하는 방식은 계정 보안과 약관 양쪽에서 문제가 된다. 현재 설계인 "사용자가 한 번 직접 로그인하고 `data/naver-profile` 에 세션을 남긴다"를 유지한다.

**ChatGPT·Gemini 웹사이트를 브라우저로 자동 조작하지 않는다.** README 에 명시된 방침이다. 해당 서비스 약관이 자동화 접근을 막고 있어 계정 제재 위험이 있다. AI 가 필요하면 공식 API(Gemini) 나 로컬 모델(Ollama)을 쓴다.

**`data/naver-profile` 을 삭제하거나 커밋하지 않는다.** 로그인 세션이 들어 있다. 삭제하면 사용자가 다시 로그인해야 하고, 커밋하면 세션이 유출된다.
